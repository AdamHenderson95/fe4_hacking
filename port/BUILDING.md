# fe4port source

Layout
- `src/main.c` — frontend (SDL2): ROM discovery, translation cache, video/audio/input, saves.
- `src/menu.cpp`, `src/menu.h` — the in-game menu (F1), built with Dear ImGui 1.91.5 (put it in
  `ext/imgui`); `src/font_roboto.inc` is the menu font (Roboto, Apache 2.0) as a compressed array.
- `src/music.c`, `src/music.h` — custom music: an MSU-1 chip ($2000-$2007, hooked in `src/snes/snes.c`) playing
  files from the music folder (OGG / FLAC / MP3 / WAV / MSU-1 PCM; decoders in `third_party/audio`:
  stb_vorbis 1.24, dr_flac, dr_mp3, dr_wav, public domain / MIT-0). `src/fe4music_patch.h` (made by
  `tools/music_patch.py`) hooks the game's song start ($80:968A) and fades ($80:8FD5); see ROM_MAP "Music".
- `src/cheats.c` — Cheats menu: the player's units from the army lists in RAM (layout in the file header).
- `src/padmap.h` — gamepad bindings (SDL button names, triggers as pseudo-buttons) shared by the frontend and menu.
- Automatic speed-ups (main.c) read three RAM values after every frame: the text pointer `$186A`
  (24-bit; moved recently = text being written), the frame handler `$00D7` (`$C144` = battle scene) and
  the army whose phase it is `$0D91` (0 = player). Debug: FE4_SPEEDLOG=1 prints changes; FE4_VPAD=script
  attaches a virtual gamepad for tests.
- `src/mods.c` — the mods folder: .ips/.bps patches applied at startup in load order (mods/load_order.txt).
- `src/kit.c` — runs fe4kit (BuilderOfTheHolyWar.exe, or FE4KitEditor.exe from older kits, or fe4rando.py with python3) in the background for the
  randomizer window: `rando --list-tsv` for the options, then `rando ROM out --ips ... --log ...`.
- `src/fe4wide.c`, `src/fe4wide_data.h` — widescreen: what the extra area shows, and the switchable
  unit-window patch (generated by `tools/fe4widepatch.py header src/fe4wide_data.h`).
- `src/fe4hover_data.h` — the switchable map hover box patch (MT/HIT/AS/AVO), generated by
  `tools/fe4hover.py header src/fe4hover_data.h` (`tools/fe4hover.py kitdata fe4hoverpatch.py` writes the
  same patch for fe4kit's "unit stats" build option). Both patches read an on/off word in ROM that the
  frontend writes when the option changes, so they switch while the game runs.
- `src/rc/recomp.c` — the 65816 → C recompiler. One C function per block (entry address + e/m/x
  flag state), emitted with exactly the bus reads/writes, idle cycles and interrupt polls of the
  LakeSnes interpreter so the two can be compared instruction by instruction.
- `src/rc/rc_rt.c` — runtime helpers called by generated code, block table, dispatcher, coverage
  recording (the "learning" of new block entry points).
- `src/rc/rc_jit.c` — compiles generated C in memory with libtcc.
- `src/rc/rc_gen.h` — the self-contained interface generated code is compiled against.
- `src/snes/` — LakeSnes (dinkc64 fork, MIT) with per-instance PPU state and a `brk` flag so
  compiled code can stop at frame events.
- `tools/lockstep.c` — verifier: interpreter vs recompiled, compared after every block and frame.
- `tools/lsrun.c`, `tools/emu.py`, `tools/movie.py` — headless runner, Snes9x reference harness,
  input scripts.

Build (Linux, for testing)
```
make work/recomp work/lockstep work/fe4       # needs SDL2 dev files, ext/tcc-linux (TinyCC), ext/imgui
./work/lockstep rom.sfc work/ch1.txt 20447    # verify; exits non-zero on the first mismatch
```

Build (Windows, cross-compiled with mingw-w64)
```
make win/FE4.exe     # (music decoders are in third_party/audio)
                     # needs ext/sdl2w (SDL2 mingw devel 2.30.9), ext/tccw (TinyCC built as libtcc.dll), ext/imgui
```

Coverage workflow
1. Run with coverage recording (`lockstep --cov out.txt`), which lists block entry points the
   interpreter fallback had to execute.
2. `work/recomp rom.sfc entries.txt work/gen.c` translates them; rebuild; repeat.
3. Ship the merged entry list as `fe4port.cov`. It contains only addresses.
